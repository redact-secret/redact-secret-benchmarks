# Accept evidence snapshot-2026.10.05 on credential-eval v0.1.0-alpha.5 with the published @redact-secret/core 0.1.0-beta.13 as the credential qualification evidence

Accepted by the owner of the repository, Milo Kang, on 2026-10-05 (#680, #690, #697, #698). **This candidate supersedes the evidence candidate `snapshot-2026.10.04.4`** (never accepted; its prepared acceptance patch is removed) and replaces the accepted `snapshot-2026.10.04.3` on credential-eval alpha.4 / `@redact-secret/core` beta.12. The owner fields were set from this decision: `new.acceptedOn` and `new.acceptedBy` of the authority file and `candidate.ownerAcceptance` of `benchmarks/evidence-adoption.json`.

## Context

`snapshot-2026.10.05` (credential-evidence tag, source commit `225f7ae74a986a40fe857371b393ebfdb7d2268a`, manifest `sha256:510836b02c271bec28797cbbc71a8ee1ad4cf9a86fd644884116b1b68c5bacef`; 6,524 materialized fixtures, 6,519 exported to credential-eval and 5 not exported for invalid UTF-8) is the last snapshot of this evidence line. Against the accepted `.04.3` it adds 70 cases, removes none and changes 8: 2 regrouped, 3 re-authored in `.04.4` (the Twilio cases) and 3 whose expected spans credential-evidence corrected in PR #225 / ADR 0021 (`service-account-key-file` pretty and minified JSON now end at the END footer, RFC 7468; `aws-credentials-file-two-profiles` lists the two key ids as `companion` spans). Against `.04.4` only those 3 change. Review state is unchanged: 96 maintainer-only fixtures, 0 independently reviewed.

It was verified (manifest digest, asset digests, `release:verify`, engine alpha.5 preflight through the #690 entry point) and replayed officially on credential-eval `v0.1.0-alpha.5` (revision `c1802a6b7c81f9ef16b0b70778be293821d7a31d`) with the PUBLISHED `@redact-secret/core` 0.1.0-beta.13: CI run 37296823599 (archive `official-runs-registry-37296823599`, replay copy `official-runs-37296823599`), plain and methods, two engine runs each with equal semantic digests, linux-x64. The unpublished core build 1e45cecf is **not** part of this acceptance: it stays an exploratory, internal candidate and no public claim names it.

**Contrast with the previous snapshots, by semantic id** (`scripts/contrast-snapshots.ts`, `docs/generated/evidence-adoption/snapshot-2026.10.05.contrast.md`): the control against `.04.4` (run 37241828378) differs only in the 3 corrected fixtures (service-account-key-file pretty and minified: PARTIAL to EXACT for flare-redact, gitleaks, openredaction and redact-secret; aws-credentials-file-two-profiles: the key ids no longer count as collateral; their generated variants and assertions follow), 0 unexplained, 0 regressions. Against `.04.3` (control run 37220835061) the same plus the 3 Twilio cases re-authored in `.04.4`, 0 unexplained, 0 regressions. The same comparison of the unpublished candidate (runs 37253769074 and 37235723441) is in the same file.

## Decision

Accepted by the owner, Milo Kang, on 2026-10-05:

1. **(a)** `snapshot-2026.10.05` on credential-eval alpha.5 with the published `@redact-secret/core` 0.1.0-beta.13 is the accepted public evidence population. The engine pin, the product pin, the recorded runs, the regenerated overlays, the parity report and the renewed authority file in this change are the active evidence. The old `.04.3` floors runs stay as `historicalRuns[]` receipts (alpha.4, beta.12), never as evidence of the new pin.
2. **(b)** The owner authorises going to production (`npm run go-production`) after acceptance, provided zero regressions, zero unexplained differences, every gate green, `develop` green and staging verified. Production is a separate act: this ADR does not record a deployment.
3. **(c)** The owner decides to apply the #698 triage settlements to `benchmarks/review-ledger.json`: 364 resolved and 30 not-assertable rows keyed by the final occurrence identities of run 37296823599 (`docs/generated/evidence-adoption/snapshot-2026.10.05.ledger-settlements.json`). Of the 368 resolved and 30 not-assertable proposals of the `.04.3` triage, a proposal is applied only where the same occurrence (case, peer, disagreement, variant, content digest, expected spans and findings) exists in the accepted run and the accepted triage proposes the same settlement; 4 resolved proposals are not applied because the case was re-authored or its observation differs (the Twilio cases). Rows are `resolved` only where the reference matches the evidence's own expected result exactly and the divergence is the peer's (never peer acceptance), and `not-assertable` only for T0 pending fixtures (decided class `differential.t0-pending-fixture`). The 63 occurrences the accepted triage would also settle but that have no identical settled counterpart in the previous snapshot (61 of the cases the new snapshot added, 2 whose observation differs), and every occurrence the triage leaves open, are NOT applied: they read unresolved. A settlement that rests on a maintainer-only record says so in its note; none is an independent review. The owner also confirms the 13 provisional product-scope statements of the triage (netrc, kubeconfig user token and client key, HTTP session cookie, Azure SAS, S3-presigned and GCS-signed-URL carriers) as **the owner's product-scope decision, based on the product's own documentation** (`scanners/product-scope.json` `ownerConfirmation`, #622); they are not a statement of the core maintainers beyond redact-secret#1203 and PR #1204.
4. **(d)** The disclosure wording stays: "Maintainer-reviewed (independent review pending)" and, in Korean, "메인테이너 검토 (독립 검토 대기)", with the maintainer-only counts read from data. Owner acceptance is not an independent review.

The legacy oracle is regenerated at the same release (beta.13): parity 42,611 values compared, 0 unexplained (`docs/generated/qualification-parity.json`). Two causes were added to recognise this acceptance's differences: `owner-ledger-settlement` (the new path reads more occurrences settled than the legacy mapping, exactly the 394 owner-decided rows) and the added flagged control as a `canonical-evidence-membership` false alarm.

## Consequences

- **Status changes against the previously public accepted state (`.04.3`, alpha.4, beta.12)**: 123 stable, 11 provisional, 1 pending, 0 unsupported (before: 116, 18, 1, 0); support matrix 136 stable, 15 provisional, 5 pending, 17 unsupported (before: 126, 25, 5, 17). Eight families move from provisional to stable by the owner's ledger settlements and nothing else (`aws-access-key`, `deepgram-api-key`, `gitlab-token`, `google-api-key`, `heroku-api-key-legacy`, `npm-token`, `stripe-token`, `twilio-auth-token`): their only reason was unresolved gate-peer differential occurrences, each now settled per occurrence by the rule above. One family moves from stable to provisional by the added cases (`aws-secret-access-key`: 6 unresolved differential occurrences of added cases, 14 metamorphic and 2 mutation failures of the reference on added cases). The other provisional families stay provisional with their reasons (`github-token` and `twilio-api-key-secret` carry unresolved differential occurrences, `sendgrid-token` also failed assertions on fragment and encoded cases, the T3 policy families and the empirical ones keep their own). No status is restored by dropping hard cases, by counting unmeasured cases as misses or by peer acceptance. A larger denominator is not an improvement and a lower stable count is not a regression of the product.
- The 57 root causes of the `.04.4` added cases are classified by the core agent (redact-secret#1205, PR #1206, merge 422e43e3dc1fb02536d9c617097fd45e78a92759): 24 base cases, 12 encoded carriers, 5 fragments, 4 unsupported feature scope, 1 contract pin, and 2 in-contract bugs fixed in unreleased core main 422e43e3 and NOT yet measured. Beta.13 and core 1e45cecf behave identically on the 70 added cases. The 5 root causes of the two fixed cases stay open and linked until a replay on a build that carries them.
- Evidence corrections that credential-evidence owns (core #1203, #1205, credential-evidence#221) are proposals, never applied here.
- Rollback is reverting the acceptance commit, or setting the authority file's `authority` back to `legacy` (`docs/specs/qualification-cutover.md`). The ledger rows are additive: removing them returns the previous reading.
