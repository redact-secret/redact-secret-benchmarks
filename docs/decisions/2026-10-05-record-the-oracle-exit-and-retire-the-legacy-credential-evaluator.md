# Record the oracle exit for @redact-secret/core@0.1.0-beta.13, keep the protected-holdout kernel, freeze the legacy review queue, and retire the legacy evaluator only where nothing reads it

## Context

#660, part of the cleanup epic #651. The [switch ADR](2026-10-02-switch-credential-qualification-authority-to-the-new-path.md) made the new path the authority for credential qualification and kept the legacy path as the
oracle for a bounded period. Its exit condition (`legacy.oracle.exitCondition` in `benchmarks/qualification-authority.json`, decision 6 of the switch ADR) has three parts: a further published release qualified through the
new path and compared with the legacy path (parity regenerated, 0 unexplained); the rollback rehearsed against that release; and a removal PR that lists each file's callers first. The record of each part is in
[the cutover record](../specs/qualification-cutover.md):

- `@redact-secret/core@0.1.0-beta.13` was accepted by the owner on 2026-10-05 ([the acceptance](2026-10-05-accept-snapshot-2026-10-05-on-credential-eval-alpha-5.md)); `docs/generated/qualification-parity.json`, regenerated at beta.13, compares 42,611 values with 0 unexplained and is the report `new` cites.
- The rollback was rehearsed against beta.13 on 2026-10-05 ([the rehearsal](../specs/qualification-cutover.md#rehearsal-of-the-rollback-against-beta13-2026-10-05-660)): both values build and recount and the committed authority file is byte-identical before and after.
- The removal callers inventory is the six-column table of the cutover record, checked against the tree by `npm run legacy-inventory:check`; each removal pull request lists its callers per removed file.

The cutover record said the exit "stays the owner's decision" and that nothing may be taken on the owner's behalf. This record is that decision.

## Decision

These are the owner's decisions, Milo Kang, given explicitly in the #660 session on 2026-10-05, and recorded here as such. This record asserts nothing about the product (the boundary rule: this repository measures and records).

1. **The oracle exit condition is met for `@redact-secret/core@0.1.0-beta.13`.** It is recorded as `legacy.oracle.exit` in `benchmarks/qualification-authority.json` (owner, date, release, the parity report, the rehearsal anchor, the inventory command and this decision),
   validated by `schemas/qualification-authority-v1.json` and `benchmarks/qualification/authority.ts`. `authority:check` keeps it honest while the value is `new`: the exit must be for the release `new` is authorised for, cite the parity report `new` cites, and name an accepted decision and a rehearsal
   heading that exists. The exit is a record, not a switch: **`authority` stays `new`**, nothing is flipped, and the exit deletes nothing by itself. It permits removal pull requests, each bound by the caller inventory. The authority file gains no new reader (`AUTHORITY_READERS` is unchanged), so
   the gate's reader table needs no change. The 2027-01-02 review in the switch ADR is satisfied by this exit.
2. **The protected-holdout kernel is kept.** `credential/execution.ts`, `normalization.ts`, `reporting.ts`, `review.ts`, `assertions.ts` (and `method-common.ts`, `holdout-method.ts`, which they use) stay, with everything else the protected holdouts need. The holdouts do not get a new evaluator:
   a new code path under the protected lifecycle is a protected-lifecycle change, which no cleanup may make. Their inventory rows stay `keep`/`other-domain`.
3. **The legacy review-queue mapping is frozen as durable evidence.** `benchmarks/support/legacy-review-queue.json` carries the legacy engine's review queue over the development partition (the 4,268 differential entries the re-key maps, and the count of the 8,845 mutation entries it only
   counts), bound by a SHA-256 digest of its canonical occurrences and recording its provenance (the engine commit it was computed at, the ledger and suite digests, the `@redact-secret/core` version it executed). `benchmarks/qualification/legacy-review.ts` now reads that file and the ledger; it no longer runs the legacy engine
   and no longer imports `runner`, `execution`, `contract` or `peer-observations`. A future repin derives its inputs (`qualification:derive-inputs`, `qualification:ledger-rekey`) from the new path, the snapshot and the methods artifact, and the engine need not live on for it.
   The file is never regenerated by the repository: the digest binds it (`qualification:ledger-rekey --validate` and a unit test fail a file that differs from its digest), and its provenance names the commit whose `legacyReview()` computed it, which stays in history.
   **Verified equal, not assumed:** with the frozen queue, `npm run qualification:ledger-rekey -- --snapshot <snapshot-2026.10.05> --methods-run <canonical methods artifact> --check` reports that `benchmarks/support/public-review-ledger-map.json` matches the derivation, byte for byte, the same result the engine-computed queue gave before this change.

## What this change removes, and what it deliberately does not

Removed (each file's callers are listed in the pull request; every remaining reader was re-pointed first, tests included): the whole of `benchmarks/engine/` (eleven one-line re-export shims; the 14-line development entry point `runner.ts` moved next to `execution.ts` as `credential/runner.ts`), `benchmarks/methods/` and
`benchmarks/operators/` (thirteen re-export shims of the credential domain), the `benchmarks/lib/` shims `lattice`, `scoring`, `findings-by-path`, `run-summary` and `accounting`, and the three credential-domain shims `evidence.ts`, `methods/common.ts`, `methods/holdout.ts`. Every importer now names the module that holds the code. No implementation line changed.

Not removed, because a caller remains or an authoritative output would change. The cutover record's inventory states each blocker per file and `legacy-inventory:check` holds the callers current:

- **The candidate and qualification lanes (C5, #657).** `eval:qualify`, `eval:candidate`, `eval:classify`, `eval:matrix` and the legacy matrix consumers (`eval:publish:matrix`, the dossier roadmap, the domain index) still run on the engine in `publish-site.yml`, and their outputs are published. The candidate diff and the saved baseline are read from artifacts
  by an operator-dispatched replay (`qualification:candidate-diff`), but a push holds no candidate artifacts, so the staging publish still measures the candidate in process. Replacing it needs a candidate official run at an exact tarball digest, which is a dispatch. So `credential/runner`, `contract`, `cases`, `methods/`, `operators/`, `classify-support`, `generate-support-matrix`, `support/evidence`, `lib/reporting`, `qualify`, `candidate` stay.
- **The legacy results the oracle pages read (C6, #658).** Under `legacy`, and for the pages not yet re-pointed, `bench`, `eval:discover` and `eval:publish` produce the files; `run.ts` and `evaluate.ts` stay. The Next `legacy` authority path is the rollback and is not removed: it has callers.
- **The Vite site (`src/`, `vite.config.ts`, `index.html`)** goes only under #543; #594's redirects are preserved.
- **PII, performance, MCP, calibration, the protected lifecycle, ledger and baseline history, parity reports, ADRs and release records** are untouched.

## Credential-eval compatibility retirement

[credential-eval ADR 0014](https://github.com/redact-secret/credential-eval/blob/main/docs/decisions/0014-compatibility-retirement-contract.md) gates every deletion on the recorded oracle exit (met above), a last-reader check with owner confirmation, preserved and marked-superseded parity evidence, a rollback tag and unchanged canonical digests, then a one-minor-release support window. From this repository's side,
the only real reader of a credential-eval compatibility item is `benchmarks/qualification/evaluation-evidence.ts`, which names the four `legacy:*` validators; it stays, and D1 (canonical validator names, `legacy:*` kept as aliases for the window) is credential-eval's step with this repository's confirmation. The legacy bench and eval renderers, `--legacy-eval-out`, the `legacy-category` seed and the oracle tools have no reader
in this repository. Nothing in credential-eval is removed by this change; its D2 to D6 proceed in that repository under its contract.

## Consequences

- `authority:check` fails if the exit is recorded for another release than the one `new` is authorised for: a repin to a new release needs its own exit, decided by the owner.
- Evidence adoption and repins no longer need the legacy engine to re-key the review ledger.
- Rolling back is unchanged: set `authority` to `legacy`. The legacy files, pages and checks remain, and are not retired by the exit.
- The next removal pull requests are unblocked by the exit but gated by their callers, in the order of the cutover record: C5 (candidate and qualification lanes), then C6 (the legacy-file pages), then the entry points and package hooks.

## Alternatives rejected

- **Give the protected holdouts their own evaluator** so the kernel could go. It changes the protected lifecycle's code path; the owner decided to keep the kernel.
- **Keep running the engine for the re-key.** It keeps the engine alive for a mapping whose legacy side no longer changes.
- **Regenerate the legacy queue on demand from a pinned engine.** It needs the engine, the development corpora and live scanner execution for a value that is evidence by now.
- **Remove the candidate lane now and read candidate results from the last accepted run.** Released observations must never stand in for a candidate run (#657).
- **Flip `authority` or retire the rollback with the exit.** The exit is the owner's record that the oracle comparison is complete, not a removal of the one-value rollback.
