# Disclose the optional scanner on every report, keep the retained OpenRedaction measurement, and show observation origin apart from scope evidence

## Context

Two follow-ups of epic #723 were paused until the report scalability epic (#785) shipped. #785 is done and staged, and the four-scanner default (#812/#813), credential-eval alpha.16 and core beta.14 are pinned, so both can finish. They are the same kind of work: what a published report says about what was not measured and where an observation came from.

**#763.** The contract says an affected report states "OpenRedaction default: not measured in this run (optional)", names why, and links the last measurement. Reading the live build showed three gaps:

1. Only `/evaluation/qualification/` said it. The credential report pages, the comparison accuracy page and `/evaluation/scanner/` listed four scanners and dropped the fifth without a word.
2. The pointer to the last measurement was empty. `lastMeasurementOf` reads `benchmarks/official-runs.json` (`runs[]`, then `historicalRuns[]`). The alpha.15 acceptance (`e16959f1`) moved the alpha.5 runs out of `runs[]` and the registry has no `historicalRuns[]` since, so building the view from the recorded alpha.16 artifacts printed `last measurement: none recorded` and the overview said "No earlier measurement of it is recorded". That is false: the 2026-10-05 runs of the OpenRedaction default (engine alpha.5, CI run 37296823599) exist, and the archive release `official-runs-registry-37296823599` still holds their artifacts. Re-reading that archive, `public-evidence-snapshot/artifact.json` has the byte digest the old registry recorded (`sha256:31ebec73...`), lists `openredaction` as a complete scanner, and carries no `native_labels` and no `scope_accounting`.
3. A pointer cannot say what the old run's scope accounting looks like, so a reader could take a missing count for a zero.

**#724.** The scope block is read from the artifacts of the current runs. Reading the recorded alpha.16 artifacts (run 37630100920, the four required scanners): no `scope_accounting`, no `native_labels`, and in `non_semantic.execution` no per-scanner `origin`, no `origin_reason` and no `reuse`. The block therefore shows `Not accounted` and Unknown for every required scanner (the engine has a reviewed disposition table only for OpenRedaction), which is correct and was never documented per run. The earlier note that "measured/reused origin lives in non-semantic telemetry and run receipts, which the reader does not take as evidence" left the criterion open.

What the recorded sources carry about origin: the registry and run records carry artifact digests, determinism runs, the scanner list and `omittedOptionalScanners`, and no per-scanner origin. The artifact's telemetry has `origin`/`origin_reason`/`reuse` (RunArtifact v1.6) but the engine writes them only for a run that offered observations for reuse, and an official run never does (the driver refuses reuse, `docs/specs/accuracy-reuse.md`). The telemetry is byte-verified: the view job checks each archived artifact against the registry's byte digest.

## Decision

1. **The roster keeps the last measurement when the registry does not.** `optionalScanners.<id>.retainedMeasurements[]` holds facts about a retained official measurement: recording date, engine, archive release, asset and CI run, and each run's id, configuration hash, semantic and byte digest, scanner version and scanner configuration hash, plus whether the runs carry native labels. The registry's `runs[]` and `historicalRuns[]` win when they hold a run of the scanner; the retained record is the fallback and the view labels it `retained`. The OpenRedaction default carries the four alpha.5 runs of 2026-10-05, extracted from `06713ee6:benchmarks/official-runs.json` and re-checked against the archive's byte digest. No count is recorded, so nothing here can be mistaken for a current result. `official-runs:check` refuses a retained run that the registry also lists, one not older than the active runs, or one on a scanner that is not optional. The roster is not a policy-revision component, so no pin, authority, ledger, threshold or status moves.
2. **Every affected report says it.** The qualification view's `scannerRoster.notMeasured` reaches the pages through `PipelineStamp` (every credential report page, `/evaluation/credential`, `/comparison/accuracy`) and `/evaluation/scanner/`, through one block, `OptionalScannerNote`: the contract sentence, the reason, the pointer (run, engine, configuration, date) and a link to the qualification page, which carries the full pointer with the archive that keeps the artifacts. A legacy measurement states that its native labels are unavailable, so its scope counts are Unknown and never zero. The scanner never gets a row, a count or a zero, and is never spliced into another run or profile. A page built from a run that measured every optional scanner, or from a view that predates the roster, says nothing.
3. **Observation origin is provenance, shown apart from scope evidence.** The adapter reads `origin`, a vocabulary-checked `origin_reason` and the `reuse` digests from `non_semantic.execution` (`observation-origin.ts`), nothing else of it, and adds `origins` and `methodsOrigins` to each population of the view (additive in v1). They feed no count, outcome, denominator, floor or status; a test holds the rest of the view equal when only the telemetry differs. The qualification overview shows them in their own block, `ObservationOrigins`, under the scope block, with three states: scanned in this run, reused from an earlier verified run (with the receipt digests), and **not recorded**. Not recorded is what an artifact says when the run offered no observations for reuse, and for every older engine; it is never rendered as scanned in this run, because the artifact does not say so.
4. **Disposition of the display limit.** With the recorded sources as described above, the honest display of origin for the current official runs is "not recorded" for every scanner. That is the stated limit: the data cannot say more, the display says exactly that, and a run whose telemetry does record fresh or reused shows it without any further change. We do not infer "fresh" from the run class.
5. **Accounting availability is documented per scanner and run** in `docs/specs/qualification-adapter.md` ("Observation origin"): at engine alpha.16 none of the four required scanners has a reviewed disposition table, so every scope state is `not-accounted` with Unknown counts; the retained alpha.5 OpenRedaction artifacts are `legacy-native-label-unavailable`. The OpenRedaction default's own scope accounting (engine alpha.11+) exists only in exploratory local runs (#759); making it official needs the optional, owner-approved measurement and is not required here.
6. **No new measurement.** No official-runs dispatch, no all-pattern scan, no engine release, no repin, no authority, ledger, threshold or support-status change.

## Consequences

- A reader of any credential report page learns that OpenRedaction's default profile is not in the run, why, and where its last measurement is, with the engine, configuration and date, instead of finding a silent absence.
- The pointer survives repins as long as the roster record exists. A later repin that keeps `historicalRuns[]` takes precedence, and the retained record can then be removed.
- If the engine later records scope accounting for the required scanners, or an exploratory run records `origin: reused`, the existing blocks show it; no page change is needed.
- Tests build synthetic states (fresh, reused, not recorded, optional left out with a retained or historical pointer, legacy native labels unavailable) and assert no ledger value.
