# Generated mutations

Status: evaluation method definition v1

## Purpose

Systematically explore detector behavior near reviewed fixtures using
registered, deterministic operators. Generated mutation expands coverage; it
does not manufacture ground truth from arbitrary fuzzing.

## Inputs

- A validated source case with provenance and source hash.
- A versioned mutation operator and deterministic seed.
- An operator strategy of `preserve`, `invalidate`, or `review-required`.
- Bounds limiting variant count, size, and execution cost.

## Procedure

1. Confirm that the operator declares support for the source case.
2. Generate variants before any scanner executes.
3. Validate unique IDs, safe relative paths, UTF-8 ranges, span roles, and
   expectation strategy.
4. Run all generated bytes through identical scanner adapters.
5. Send undecidable expectations to the review queue; never score them by
   majority vote.

## Assertions

- `preserve` variants retain the source assertion.
- `invalidate` variants must be clean unless an independent policy assertion
  says otherwise.
- Generation must be deterministic and must not overwrite source fixtures.
- Invalid or duplicate variants fail the method before scanning.

## Reporting

Report operator ID and version, source and variant hashes, seed, parameters,
strategy, scanner observations, assertion results, generation errors, and
operator coverage.

## Exit criteria

A clean checkout reproduces byte-identical variants and results contain enough
provenance to recreate any failure without retaining temporary scan files.
