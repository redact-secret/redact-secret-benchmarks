# Evaluation UI gap analysis and implementation plan

Measurement-v4 loads `/results/run.json` and category reports, validates fixture corpus hashes, and renders kind × tier scanner outcomes. It has no consumer for discovery schema 2, its case/variant graph, assertions, method/detector/taxonomy/operator summaries, generation attempts, comparisons, or review queue. Qualification is a separate historical aggregate, not a discovery run or detection-quality certification.

Keep the existing benchmark/fixture routes. Reuse the shell, escaping, table/panel styles, catalog links, history routing and polling. Add `/evaluation`, `/evaluation/method/:method`, `/evaluation/detector/:id`, `/evaluation/failures`, `/evaluation/reviews`, and `/evaluation/operators`. Method and detector views derive unique affected cases separately from assertion totals; relation rows identify overlap with absolute failures on the same case/scanner. Scanner observations remain separately identifiable. Differential disagreement and T0 mutation review never enter failure totals.

Publish an explicit version-1 public projection to `/results/evaluation-v1.json` using a separate `eval:publish` command after discovery. Reject holdout rows and unknown/noncurrent source cases before publication. Allowlist metadata, assertions, transformation contracts, numeric finding counts, generation outcomes and review/comparison metadata; omit fixture bytes, raw scanner rows/configuration, arbitrary error messages, private seeds and paths. Preserve full discovery evidence locally. Validate projected structure and counts on publication and browser load; catalog hashes detect stale input. Public report is ignored like other generated results.

Load optional qualification through existing strict evidence validation and include only its allowed aggregate contract. Label its independent run/time, supportClaims:false, milestone snapshot and candidate provenance. Holdout remains aggregate-only, with no detector attribution or unique cross-scanner affected-case count invented. Do not read protected storage. Refresh milestone with the intended command if possible, then regenerate qualification using public conformance controls; never hand-edit generated evidence.

Verify projections (deduplication, review separation, malformed/stale data, publication privacy), existing unit/integration suites, TypeScript, production build, current discovery publication, direct-route reloads, empty states and desktop/mobile rendering. Document any unavailable tools or qualification refresh blockers.
