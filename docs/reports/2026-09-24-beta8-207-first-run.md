# Beta.8 #207: low-coverage hardening, first run

Issue [#207](https://github.com/redact-secret/redact-secret-benchmarks/issues/207)
raises twelve low-coverage registry families to their Beta.8 fixture profile.
This page records what was authored and what the first run measured. It is a
measurement, not a product claim (`AGENTS.md` boundary rule), and it changes no
support status: `npm run beta8:profiles` is advisory and #206 owns the gate.

## What was authored

One corpus, `beta8-207` (348 fixtures, `fixtures/generated/beta8/207.mjs`),
and the twelve registry contracts in `benchmarks/lib/assessment.ts`, each now
carrying per-field provenance (`FIELDS_207`). Every value is a `synthetic()`
seed or is built by generator code that recomputes a published checksum over a
synthetic body (Supabase sha256, Atlassian CRC32, Confluent CRC32). Nothing is
copied from a provider example, an issued credential or scanner output. No
arrival family is declared: all twelve families already map to a registry
detector.

**Scope: 348 added family-fixture assignments, above #207's 280–320 band.**
The band was the simple 40-per-family difference (312). Two things move it,
and both follow from the task's own rules rather than extra evidence: five
opaque families take the 48-fixture context profile (+8 each, +40), and the
pre-existing positives carry no `contextAxis`, so each family needs at least
six new, labelled positives to reach its positive-axis floor even where the
positive count was already met (sentry, telegram, discord). Supabase takes the
24-fixture documented profile, which lowers the total. The minimum that meets
every floor is about 337; this corpus adds 11 beyond it, mostly controls that
cover the axes #207 lists (public IDs, references, placeholders, masked values,
wrong companions, unrelated random identifiers). A reviewed amendment should
confirm or trim this.

## Contract changes

- **supabase-token: T0 → T1** on the grammar Supabase now documents
  (research #231): `sb_secret_` + 22-character random part + `_` + 8-character
  checksum, from the self-hosting page, which says hosted keys use the same
  format. The base64url alphabet and the sha256 checksum are provider code,
  recorded as provisional; the hosted checksum input is unresolved. The
  TruffleHog `supabasetoken` corroboration was dropped: it matches `sbp_`, not
  `sb_secret_`. The three pre-existing 40-alphanumeric positives fall outside
  the grammar and are now retained legacy policy expectations. Its un-probeable
  record is lifted: twins mutate the public `sb_publishable_` prefix, a segment
  width and the positional `_`.
- **atlassian-api-token: pattern** now admits the optional `=<8 uppercase hex>`
  suffix every observed 192-character token carries (redact-secret#643,
  confirmed once on a maintainer-issued key). The 100-character body floor is
  unchanged. The CRC32 suffix is provisional tool evidence and is not in the
  pattern, so no checksum-only twin is scored.
- **heroku-api-key-legacy: review rewritten.** The 41-character `HRKU-<uuid>`
  and 65-character `HRKU-AA` generations are provider-documented widths
  (changelog-items/3175), not undocumented variants, and belong to the current
  OAuth family (#209). The stale "every gated rule flags the app id" tradeoff
  now records that the product excludes identifier-shaped keys since
  redact-secret#714. Uppercase hex and the 40-hex token in the authentication
  article are unresolved, not asserted either way.
- **confluent-cloud-api-secret-legacy: review corrected.** The gitleaks class
  is `(?i)` (it misses only `+` and `/`, not uppercase). The 60/64 ambiguity is
  preserved: positives use 64, and no fixture asserts silence on a 60-character
  value. A current `cflt` secret appears only as a twin scoped to this family.
- **bearer-token:** `contextGated: true`, so the context-48 profile applies.
  Scoring is unchanged: bearer was already policy-scored.
- **Un-probeable records lifted** for discord, telegram, both Sentry families
  (value twins, each property cited in `twinSource`) and both Twilio families
  (context twins, which #207 requires for opaque values). Only `vercel-token`
  remains un-probeable.
- `scanners/families.mjs` now maps the product's two Confluent detector ids,
  so the scoped `cflt` twin can tell sibling co-detection from a legacy-family
  finding. Without the mapping, every product finding on it failed closed.

### Product findings (recorded open in the review ledger, not resolved)

1. **atlassian-api-token, partial redaction:** all 10 realistic 192-character
   tokens are redacted only up to the `=` and leave `=` plus the 8 hex characters
   (the CRC32) exposed. gitleaks matches the whole token.
   Class `confirmed-partial-redaction/atlassian-api-token`.
2. **supabase-token, twin over-acceptance:** the product floor
   (`at_least(20, is_alnum_dash)`) flags a 21-character random segment, a
   9-character checksum and a `-` in place of the positional `_`, none of which
   fit the documented grammar. The `sb_publishable_` public-prefix twins stay
   clean. Class `confirmed-boundary-false-positive/supabase-token`.
3. **heroku-api-key-legacy, coverage:** a multi-line `.netrc` (keyword on the
   `machine` line) and `heroku auth:token` output (value on the next line) are
   missed; trufflehog finds the latter. #232 asked for both axes. There is
   also one false positive: an app UUID in a Platform API URL path.
4. **Keyword-gate precision** (controls flagged): a 32-hex md5 digest on a
   `twilio` line (`twilio-auth-token`), a sha256 image digest on a `confluent`
   line (`confluent-cloud-api-secret-legacy`), the `YOUR_ACCESS_TOKEN`
   placeholder after `Bearer` (`bearer-token`), and an SK+AC SID pair flagged
   by `generic-token`.
5. **Cross-family:** an Atlassian account id (`712020:<uuid>`) is reported by
   the product's `telegram-bot-token` detector. The same value also satisfies
   this corpus's loose telegram contract (`^[0-9]{5,}:[A-Za-z0-9_-]{34,}$`).

## Blockers and what stays human-only

- **Empirical-40 is authored, not earned.** #205's provider-issued
  observation records do not exist yet. The six empirical families meet the
  fixture structure only; none claims empirical stability. The recorded
  blocker is the missing observation gate (at least five observations across
  two accounts or projects and two issuance dates).
- A new legacy Heroku or Confluent credential cannot be issued, so an existing
  pre-cut-over key is the only possible corroboration. It is optional, not a
  gate.
- Hands-on checklists in #231, #643, #646, #649, #658–#662 remain
  corroboration: Supabase hosted layout and checksum input, Atlassian CRC32,
  Telegram 34 vs 35 body width and `AA` lead, Discord current widths, Sentry
  internal-integration prefix, and Twilio alphabet.
- Firebase 162/167/183-character bodies (late-2016 keys) are outside the
  140-character contract. They are recorded, not asserted either way.
- Not used as controls, because each is a secret of another kind: `ATCT`/`ATBB`
  Atlassian tokens, `sbp_` PATs, legacy Supabase `service_role` JWTs, `cflt-scim_`
  tokens, Heroku OAuth client secrets and refresh tokens, `HRKU-<uuid>`, the
  Telegram Serverless `app<id>:` token, Discord webhooks, and bare 64-hex values
  beside a sentry keyword (legacy user tokens).
