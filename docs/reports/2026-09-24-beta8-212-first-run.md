# Beta.8 #212 first run: second-wave arrival families

Issue: [#212](https://github.com/redact-secret/redact-secret-benchmarks/issues/212).
Research: #226 (Perplexity), #227 (Fireworks AI), #228 (Pinecone), #229 (Slack
user token), #230 (GitLab runner authentication token). Product counterpart:
redact-secret/redact-secret#730 (blocked by #726).

This report records the first measurement of the `beta8-212` corpus. It
changes no support status and asserts no product behaviour. Every value in the
corpus is a `synthetic()` seed or is built by generator code from synthetic
bytes (the GitLab routable checksum). None is provider-issued, scanner-reported,
copied from a provider example or derived from a real credential.

## Run conditions

- Date: 2026-09-24. Mode: published. `redact-secret` is `@redact-secret/core`
  0.1.0-beta.7 (default detectors).
- Peers: gitleaks 8.30.1, trufflehog 3.97.4 (`trufflehog --version` checked in
  the same shell as each run), flare-redact 1.6.1.
- Command: `npm run eval -- --detector=<target>` for each of the six targets.
- An earlier attempt was discarded. In it, gitleaks errored ("Ambiguous or
  unmappable scanner finding") on multi-line `curl ... \` fixtures, because its
  `curl-auth-header` rule reports the first line of a continued command. Those
  fixtures were rewritten as single-line commands before the run below. No
  expectation changed.

## Lexical separability (decided before authoring)

| Target | Separates from confusables by | Not claimed |
| --- | --- | --- |
| `perplexity-api-key` | `pplx-` + 48 alnum; model ids (`pplx-embed-v1-0.6b`), packages, hosts, placeholders and masks carry no 48-alnum run | Analytics API key, MCP OAuth tokens, historical shapes |
| `fireworks-ai-api-key` | `fw_` + 22 or 24 alnum; `fw_id`/`fw_version`/`fw_spec` and the console display prefix are short | `fpk_` Fire Pass, unprefixed legacy keys, any other width |
| `pinecone-api-key` | `pcsk_<5-6>_<63>`; UUID ids, index hosts, environments and `pcsk***` masks | `pckey_` (documented, never observed; unresolved) |
| `pinecone-api-key-legacy` | no bare-value rule: a UUID is identical to key/project/service-account ids, so the family is context-gated | bare UUIDs anywhere else |
| `slack-user-token` | `xoxp-` + three numeric sections + secret section, no width or alphabet frozen | `xoxe.xoxp-` rotating tokens, the `xoxp-1-…` service token, `xoxc-` |
| `gitlab-runner-authentication-token` | `glrt-` + 20-char body (optional `t<hex>_`), or the routable grammar whose base36 length holder and CRC32 are re-checked by `validate` | `glrtr-`, instance prefixes, unversioned routable form |

No candidate failed separability, so none was replaced. The gitleaks
false-positive convention for Perplexity (`pplx-` + 48 `x`) satisfies the
contract pattern and is therefore not authored as a control.

Which product detectors already catch these shapes: the product's
`slack-token` detector covers `xoxp-` (7/8), and its `gitlab-token` detector
covers the legacy and `t3_` runner shapes but only redacts routable tokens up
to their first dot. That leaves the `.01.<length><checksum>` tail (13 bytes)
exposed. Perplexity, Fireworks and Pinecone are covered only where a generic
`Authorization: Bearer`, JSON key or assignment context applies.

## Open questions

  - flare-redact accepts a 47-character Perplexity body.
  - trufflehog's Slack rule co-detects the missing-secret twin.
  - gitleaks does not validate the routable checksum.
  - `benchmarks/detector-inventory.json` lists trufflehog's Pinecone detector as feature-gated, yet 3.97.4 reported every `pcsk_` positive.
- Human-only corroboration (#226-#230 checklists):
  - Perplexity body width and alphabet.
  - Fireworks widths and alphabet.
  - Pinecone `pcsk_` versus `pckey_` and the label width.
  - Slack widths, alphabet and `xoxe.xoxp-` scope.
  - GitLab `glrtr-`, instance prefix and `t<hex>_` window.
- `slack-user-token` is contracted here, but the taxonomy still maps
  `slack:user-token` to no detector, while the product's `slack-token` already
  claims `xoxp-`. The mapping decision belongs to #726/#730.
