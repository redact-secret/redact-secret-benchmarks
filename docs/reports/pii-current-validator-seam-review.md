# Current PII validator and peer measurement seams

Reviewed 2026-10-08. This is a source review, not a scanner execution, primitive conformance result, protected activation or owner acceptance.

## Product validator boundary

Target: `redact-secret/redact-secret` commit `5696d7e1a2950bdf54fa21244f351e1c4b171f25`, artifact qualification run `37772337995`.

The product contains real bounded validator implementations. `structured_validators.rs` defines three registrations: `luhn/1` (19-byte bound), `iban-mod97/1` (34 bytes), and `us-ssn-allocation/1` (9 bytes). Its registry, provenance, evidence and failure types are `pub(crate)`. `StructuredValidatorRegistry::validate` returns valid evidence or `UnknownValidator`, `CandidateTooLong`, `Malformed`, or `ChecksumMismatch`. See [source lines 11–103](https://github.com/redact-secret/redact-secret/blob/5696d7e1a2950bdf54fa21244f351e1c4b171f25/crates/secret-scan-core/src/structured_validators.rs#L11). The module itself is private in [lib.rs:170](https://github.com/redact-secret/redact-secret/blob/5696d7e1a2950bdf54fa21244f351e1c4b171f25/crates/secret-scan-core/src/lib.rs#L170). The reviewed file bytes equal GitHub's exact-commit content, blob `30cde87d846f557dff5e587d9ea3aae38dfbfcaf`, SHA-256 `816799700971336037c60a4ff1c23a26289bfc4bf9f5831e3b2d7d90c4911bb7`.

[Core #910](https://github.com/redact-secret/redact-secret/issues/910) is closed by [#921](https://github.com/redact-secret/redact-secret/pull/921). Their implemented seam answers identity and sensitivity for an authored family/range. Its output is exactly `id`, `family`, `identity`, `sensitivity`, preceded by a format/family/vocabulary/activation header. It does not emit primitive validator identity, failure outcome or bound enforcement. See the current [example input/output contract, lines 10–26](https://github.com/redact-secret/redact-secret/blob/5696d7e1a2950bdf54fa21244f351e1c4b171f25/crates/secret-scan-core/examples/pii_identity_evaluation.rs#L10), [output, lines 235–263](https://github.com/redact-secret/redact-secret/blob/5696d7e1a2950bdf54fa21244f351e1c4b171f25/crates/secret-scan-core/examples/pii_identity_evaluation.rs#L235), and [IdentityOutcome, lines 570–579](https://github.com/redact-secret/redact-secret/blob/5696d7e1a2950bdf54fa21244f351e1c4b171f25/crates/secret-scan-core/src/pii.rs#L570).

The example deliberately compiles the product's own source modules to access private items. It is excluded from the published package: [example:28–43](https://github.com/redact-secret/redact-secret/blob/5696d7e1a2950bdf54fa21244f351e1c4b171f25/crates/secret-scan-core/examples/pii_identity_evaluation.rs#L28), [Cargo.toml:14](https://github.com/redact-secret/redact-secret/blob/5696d7e1a2950bdf54fa21244f351e1c4b171f25/crates/secret-scan-core/Cargo.toml#L14). The installed JavaScript API exposes `piiActivation` ([index.ts:52](https://github.com/redact-secret/redact-secret/blob/5696d7e1a2950bdf54fa21244f351e1c4b171f25/packages/javascript/src/index.ts#L52)); activation capture records configuration, not validator outcomes.

**Disposition:** `product-validator-primitive-seam-unavailable` means the qualified installed product has no reviewed primitive-outcome evaluation interface. It does not mean implementations or a maintainer-local identity seam are missing. A bounded native source harness could call the actual registry by compiling its exact source as a local module, following the identity example's pattern. That would be new source-level measurement tooling requiring a reviewed output contract and source/binary binding. It would not prove primitive outcomes of the already qualified Node/Wasm packages, whose primitive functions are not exported. No such harness was built or run in this review. The benchmark's existing validator observer is explicitly an untrusted simulation, [validator-qualification.ts:280–342](../../benchmarks/evaluation/domains/pii/validator-qualification.ts#L280).

## Peer comparison boundary

Current official engine: `b1c097e40bad456e52f904f626cca00b69c45612`. Independently reviewed newer evaluator: `e99128f5633c5905497342623e249ad90d902800`, as recorded in [pii-peer-readiness-v1.json](../../benchmarks/pii-peer-readiness-v1.json). Its `config.rs` SHA-256 is `438262d5e41dea09a55d228eccc39bd39199ab7cd796e0b8dfae69235c1cea80`, matching that inventory.

At the newer commit, the execution CLI still constructs only `redact-secret-core`: [config.rs:25–26](https://github.com/redact-secret/pii-eval/blob/e99128f5633c5905497342623e249ad90d902800/crates/pii-eval-cli/src/config.rs#L25), and rejects every other adapter at [496–498](https://github.com/redact-secret/pii-eval/blob/e99128f5633c5905497342623e249ad90d902800/crates/pii-eval-cli/src/config.rs#L496). [scanners.rs:4–5](https://github.com/redact-secret/pii-eval/blob/e99128f5633c5905497342623e249ad90d902800/crates/pii-eval-cli/src/scanners.rs#L4) states the same limit. The adapter source inventory contains a generic process/adapter substrate and `redact_secret.rs`, with no flare-redact or OpenRedaction implementation. Upstream [#17](https://github.com/redact-secret/pii-eval/pull/17) completed that substrate and product adapter; it did not deliver those peer mappings. On this review date the open evaluator issues do not expose an implemented peer adapter handoff; #30/#34 concern protected workers, not the public peer prerequisite.

The existing engine **can** score external observations without a new kernel. `replay` accepts observation sets bound to the same snapshot and manifest, rejects duplicate scanner identities, and requires the manifest's complete scanner roster: [cmd_replay.rs:113–130](https://github.com/redact-secret/pii-eval/blob/e99128f5633c5905497342623e249ad90d902800/crates/pii-eval-cli/src/cmd_replay.rs#L113). Such a replay launches no scanner. A small standalone peer comparison is therefore technically possible after a producer pins and records real peer execution and its reviewed family/range/sensitivity mapping, offset conformance and configuration. It cannot be honestly produced now by relabelling the core adapter or throughput observations.

That standalone path is now recorded for the two published peer defaults in [Bounded local peer observations](pii-peer-local-defaults.md): eight validated public replay artifacts over the unchanged four populations, with reviewed type/range mapping and sensitivity/action withheld. It remains local exploratory evidence; the neutral diversity and ground-truth prerequisites below are still open.

[Benchmarks #576](https://github.com/redact-secret/redact-secret-benchmarks/issues/576) remains open for those neutral expectations and meaningful same-population peer artifacts. The existing credential peer adapter disables flare-redact PII and leaves OpenRedaction PII labels unmapped ([scanners/index.mjs:17–37](../../scanners/index.mjs#L17)); it supplies no reviewed accuracy mapping. Reuse the four authored public snapshots and preserve unresolved/method-restricted cells. The current schema-only populations also lack an independent diversity review. Thus the precise remaining work is reviewed peer observation production and expectation/coverage review, not EC2, protected qualification, an absent public corpus or an absent scoring engine.
