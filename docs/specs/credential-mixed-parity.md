# Credential mixed-document parity (#381)

[#381](https://github.com/redact-secret/redact-secret-benchmarks/issues/381) (Beta.11 E, parent
[#376](https://github.com/redact-secret/redact-secret-benchmarks/issues/376)) checks that the same credential
fixtures, composed into realistic mixed documents, give the same exact spans, the same sanitized bytes and the same
actions on every product surface. It measures and records; it moves no support status.

## Plan

`benchmarks/evaluation/domains/credential/mixed-parity/credential-mixed-parity-v1.json` is generated by
`npm run credential-parity:plan` from a fixed rule (`authoring.ts`) and frozen before any scan.

- **Families:** the fifteen #377 ledger families (`docs/reports/2026-09-28/beta-11-family-axis-ledger.json`, evidenced
  by the #379 corpus) and the twenty-four #860 families of #434/#436.
- **Lines:** per family, two positives on different context axes, one twin and one benign control from the family's own
  corpus, five families per document, among authored filler (logs, Markdown, chat, YAML) with public identifiers,
  placeholders and `${VAR}` references. A fixture line is bound by the SHA-256 of its content and of its wrapped line;
  the value is rebuilt from its public synthetic seed at run time and never written into the plan.
- **Spans:** each target is the fixture's own reviewed secret span, with its envelope and companions. Wraps move them
  mechanically: `line-unicode` (non-ASCII text before and after the line), `adjacent-unicode` (the value framed directly
  by `「` and `」`, bare-value T1/T2 families only), `json-escaped` (the whole fixture as one JSON string), and
  `long-line` (the fixture after one minified run longer than the 8 KiB incremental token limit).
- **Bounded oversized input:** one ~75 KiB log (over the 64 KiB incremental buffer, under the 1 MiB input limit) with
  positives at its start, middle and end.

## Checks

For every document in LF and CRLF, on each surface: whole-input `scan`, `redact(scan)` and `scanAndRedact`; incremental
sessions over deterministic partitions (single chunk, every code point, inside every target, a cut at each of a target's
first sixteen code points so prefix, delimiter and body start are all split, mid, end, between CR and LF, and three seeded
partitions); the Node `Transform` and Web `TransformStream` byte adapters over the same cuts in UTF-8 bytes plus one cut
inside every multi-byte character; whole-input limits at exactly the input size and one byte under; and an incremental
session one unit under the input size, which must fail closed without emitting a target value.

Surfaces: Node addon and Node Wasm fallback (with both stream adapters), browser Wasm (headless Chrome, the shared job
runner), the Python extension, the Rust crate and the CLI. Every surface runs the #427 job runners in
`scripts/pii-parity/` unchanged with an empty PII selection; `scripts/credential-parity/node-child.mjs` adds the stream
adapters. Unsupported operations are reported per surface (`notApplicable`), never skipped silently.

## Units and scoring

Documents and targets are the independent samples. Variants, partitions, streams, operations and surfaces are checks on
the same documents and are never counted as samples. A target is `exact`, `envelope` (covered inside its authored
envelope), `warn-only` (found but left in the text), `partial` or `miss`. A replacing finding outside every target,
envelope and companion is collateral, attributed to its line's role (positive line, twin, control, filler). A value left
in the sanitized bytes more times than in the reference output is a leak. Cross-surface parity compares each surface's
findings (in UTF-8 bytes) and output digest with the Node addon's whole-input result on the same document variant.

Run: `npm run credential-parity:measure -- --core-commit=<40-hex> --core-repo=<absolute path to a redact-secret clone>`.
Evidence lands in `evidence/860/381/<commit12>/` (keyed by the product parent, redact-secret#860): the observation (ranges, digests, no text) and the report.
