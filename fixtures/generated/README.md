# Expanded synthetic corpora

These eight corpora are generated by `build.mjs`, `regressions.mjs`,
`closed-milestone.mjs`, `detector-coverage.mjs`, and `common-formats.mjs`. Run `npm run fixtures:generate`
to rebuild or `npm run fixtures:check` to reject drift. Ground-truth ranges
come from explicit secret segments during construction, never from detection
output. No live credentials or provider verification are used. The new common
suite includes a parseable private key from a public test seed and a locally
signed JWT; neither has ever been deployed.

All fixtures carry a measurement-purpose assessment. Legacy inputs and ranges
are preserved, but malformed shapes and project masking policies are excluded
from the reviewed-format cohort. Unsupported but reviewed formats stay in that
cohort; uncertain variants are unscored. See the [full audit](../../docs/corpus-audit.md).
Historical mixed-score tables below describe older runs and are superseded for
comparative interpretation by schema v3.

| Credential formats | 27 | 27 | Nine shapes × three deterministic values |

Formats cover five GitHub prefixes (`ghp`, `gho`, `ghu`, `ghs`, `ghr`),
GitLab PAT, npm token, SendGrid key, and Slack bot token. These are nine
**shapes across five providers**, not nine providers. Source references:

- [GitHub credential types](https://docs.github.com/en/organizations/managing-programmatic-access-to-your-organization/github-credential-types)
- [GitLab token overview](https://docs.gitlab.com/security/tokens/)
- Gitleaks' published format rules for [npm](https://github.com/gitleaks/gitleaks/blob/v8.30.1/cmd/generate/config/rules/npm.go), [SendGrid](https://github.com/gitleaks/gitleaks/blob/v8.30.1/cmd/generate/config/rules/sendgrid.go), and [Slack](https://github.com/gitleaks/gitleaks/blob/v8.30.1/cmd/generate/config/rules/slack.go).

Some format references are scanner rules, so this corpus is not an independent
sample of real-world secrets. All fixtures remain **draft, pending human
review**. Values are SHA-256-derived characters from public, benchmark-specific
seeds, with known credential prefixes. They have never been provider-issued.
Syntax matching does not imply checksum validity or credential liveness.

Contexts cover bare tokens, EOF, quotes, JSON/YAML/TOML, JS/Python, Markdown,
comments, UTF-8 emoji/CJK/combining marks/BOM, CRLF, blank lines, distinct
secrets on one line, repeated secrets on separate lines, and a 72 KB prefix.
Negative controls include empty files, variable references, masks, hashes,
UUIDs, public URLs/emails, benign Base64, truncated token shapes, and prose.

No claims are made about live verification, git history, archives, binary files,
general encoded-secret handling, cryptographic key validity, or languages beyond
the text contexts listed. Structural PEM cases are covered separately below. A repeated value on the same line without exact positional metadata
still produces an explicit normalization error rather than a guessed match;
that behavior is regression-tested but excluded from scored corpora.

## Issue-driven regression expansion

**SendGrid regressions** tracks [#285](https://github.com/redact-secret/redact-secret/issues/285).
The complete 69-byte shape is exercised with base62 characters, internal
URL-safe `-`/`_`, and a trailing `-`. Each appears bare, in two provider-specific
environment fields, a generic `api_key`, JSON, quoted env, Unicode, CRLF,
Markdown, and a Bearer header. Negatives omit or shorten segments/separators,
use the wrong prefix, or contain only masks/prose. Positives are structural
test shapes; no canonical decoding, checksum, account linkage, or liveness
is claimed. Scanner findings spanning a Markdown delimiter or omitting a
trailing character count as FP + FN under the existing exact-range protocol.

**Reference syntax** follows the safe examples in milestone-6 issues
[#278](https://github.com/redact-secret/redact-secret/issues/278),
[#279](https://github.com/redact-secret/redact-secret/issues/279),
[#280](https://github.com/redact-secret/redact-secret/issues/280), and
[#263](https://github.com/redact-secret/redact-secret/issues/263). Code
expressions, interpolation, and secret-manager pointers contain no literal
credential, so their expected arrays are empty. Six literal-secret controls
exercise `api_key`, `password`, and `client_secret`, including dots, quotes,
Unicode, and CRLF. These generic credentials intentionally test a different
capability than provider-prefixed formats; report categories separately.

All policy actions count as findings, including `warn`. A false positive here
does not necessarily mean the tool would redact that input. The benchmark
tests the installed published version, currently `0.1.0-beta.4`. Reports record
actual findings against the unchanged expectations for each issue.

The **Beta.3 regressions** cohort follows the final issue decisions reviewed at
commit `530cafe9737eb5abc9702945394584aeb701d8c1`, not only the original issue
reproducers. See the [coverage matrix](../../docs/milestone-6-closed-coverage.md).
It has 59 negative fixtures and 33 positive fixtures, grouped by closed issue.
Its JSON records the target release, review snapshot, and unverified surfaces.
Connection-string positives mark only the password as secret; scanners
returning the entire connection URI receive a range mismatch rather than an
exact hit. Tutorial password exclusions follow redact-secret's intended
policy and are not universal scanner requirements.


## All-detector expansion

The `detector-coverage` category adds 248 fixtures: 198 positive files and 50
negatives. Every registered detector has at least one positive shape in three
contexts (bare, quoted text, Unicode prefix with CRLF) and two negative
controls. Together with the original suites this yields **491 files and 326
expected spans**. Contexts are text-scanning inputs, not necessarily valid
configuration files; quoted generic assignments deliberately nest quotes.

The authored shapes follow the
[beta.3 detector contracts](https://github.com/redact-secret/redact-secret/tree/34ea9b92ed8879082e99f56f8f4715ee4e4f1f35/crates/secret-scan-core/src/detectors).
This is contract-oriented coverage, not an independent sample of production
credentials. Alternate prefixes include OpenAI project/service keys, Vault
service/batch/recovery, Stripe restricted/webhook, Slack rotating tokens,
Docker organization tokens, DigitalOcean OAuth, Linear OAuth, and Vercel
token families. Some values satisfy only the detector's structural contract;
provider checksums, serialization, exact production lengths, and liveness are
not asserted. Public deterministic SHA-256 seeds generate the bodies.

Six PEM labels use base64-encoded public prose, never DER or functional key
material. The JWT has an expired payload, an example.invalid issuer, and a
fabricated signature. Connection strings use reserved hosts and mark only
password bytes; OTP URIs mark only the synthetic base32 seed. No example has
been provisioned with a provider. Negative controls include short/prefix-only
values, public-key prose/blocks, missing JWT signatures, URIs without secrets,
and generic references/masks.

The fixture tests enforce positive/negative coverage for every registered
detector, exact assignment consistency, context byte preservation, and the
nonfunctional PEM/JWT construction. They do not force scanners to match the
expected outcome. Scanner differences remain measured results.


### Measured beta.3 expansion results

On 2026-09-16, all three scanners completed the new suite on macOS arm64.
Counts below use the same 198 expected spans and 50 negative controls.

| Scanner | Version | TP | FP | FN |
| --- | --- | ---: | ---: | ---: |
| redact-secret | 0.1.0-beta.3 | 195 | 0 | 3 |
| Gitleaks | 8.30.1 | 87 | 1 | 111 |
| TruffleHog | 3.97.4 | 48 | 6 | 150 |

The three redact-secret misses are `generic-token-api-key-quoted`,
`generic-token-password-quoted`, and `generic-token-client-secret-quoted`:
nested quoted assignments in plain text. Their expected secret ranges remain
unchanged. This suite is based on redact-secret's structural contracts and
deliberately nonfunctional credentials, so these counts are not a product
ranking. Exact URI-range differences and synthetic filtering can contribute
to differences between scanners.

Validation passed: fixture identity, 75 unit/redaction tests, five real-scanner
integration tests, all 27 scanner/category executions, and the production
build. Generated JSON reports remain gitignored.

### Measured beta.4 follow-up

On 2026-09-17, the unchanged detector-coverage suite was rerun with published
`@redact-secret/core@0.1.0-beta.4`. Redact Secret scored **198 TP / 0 FP / 0
FN**: the three nested quoted generic assignments missed by beta.3 now match
exactly. Gitleaks 8.30.1 and TruffleHog 3.97.4 results were unchanged. See the
[beta.4 release comparison](../../docs/beta-4-results.md) for all nine suites.

This corpus remains the 25-family beta.3 registry snapshot. New beta.4 detector
families are not counted until their taxonomy and independently authored
positive and negative fixtures are added.
