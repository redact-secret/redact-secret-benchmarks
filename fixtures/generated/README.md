# Expanded synthetic corpora

These six corpora are generated by `build.mjs`, `regressions.mjs`, and
`closed-milestone.mjs`. Run `npm run fixtures:generate`
to rebuild or `npm run fixtures:check` to reject drift. Ground-truth ranges
come from explicit secret segments during construction, never from detection
output. No live credentials, private keys, or provider validation are used.

| Category | Files | Expected spans | Coverage |
| --- | ---: | ---: | --- |
| Credential formats | 27 | 27 | Nine shapes × three deterministic values |
| Context & boundaries | 20 | 23 | One GitHub PAT shape across text contexts |
| Negative controls | 24 | 0 | Placeholders, public identifiers, malformed shapes, ordinary text |
| SendGrid regressions | 38 | 30 | Three shapes × ten contexts, plus eight negatives |
| Reference syntax | 26 | 6 | Twenty references/expressions and six literal-secret positives |
| Unreleased fixes | 92 | 33 | Eleven closed milestone-6 detection issues with positive guards |

Formats cover five GitHub prefixes (`ghp`, `gho`, `ghu`, `ghs`, `ghr`),
GitLab PAT, npm token, SendGrid key, and Slack bot token. These are nine
**shapes across five providers**, not nine providers. Source references:

- [GitHub credential types](https://docs.github.com/en/organizations/managing-programmatic-access-to-your-organization/github-credential-types)
- [GitLab token overview](https://docs.gitlab.com/security/tokens/)
- Gitleaks' published format rules for [npm](https://github.com/gitleaks/gitleaks/blob/v8.30.1/cmd/generate/config/rules/npm.go), [SendGrid](https://github.com/gitleaks/gitleaks/blob/v8.30.1/cmd/generate/config/rules/sendgrid.go), and [Slack](https://github.com/gitleaks/gitleaks/blob/v8.30.1/cmd/generate/config/rules/slack.go).

Some format references are scanner rules, so this corpus is not an independent
sample of real-world secrets. All fixtures remain **draft, pending human
review**. Values are SHA-256-derived characters from public, benchmark-specific
seeds, with known credential prefixes. They have never been provider-issued.
Syntax matching does not imply checksum validity or credential liveness.

Contexts cover bare tokens, EOF, quotes, JSON/YAML/TOML, JS/Python, Markdown,
comments, UTF-8 emoji/CJK/combining marks/BOM, CRLF, blank lines, distinct
secrets on one line, repeated secrets on separate lines, and a 72 KB prefix.
Negative controls include empty files, variable references, masks, hashes,
UUIDs, public URLs/emails, benign Base64, truncated token shapes, and prose.

No claims are made about live verification, git history, archives, binary files,
encoded secrets, private-key detection, or languages beyond the text contexts
listed. A repeated value on the same line without exact positional metadata
still produces an explicit normalization error rather than a guessed match;
that behavior is regression-tested but excluded from scored corpora.

## Issue-driven regression expansion

**SendGrid regressions** tracks [#285](https://github.com/redact-secret/redact-secret/issues/285).
The complete 69-byte shape is exercised with base62 characters, internal
URL-safe `-`/`_`, and a trailing `-`. Each appears bare, in two provider-specific
environment fields, a generic `api_key`, JSON, quoted env, Unicode, CRLF,
Markdown, and a Bearer header. Negatives omit or shorten segments/separators,
use the wrong prefix, or contain only masks/prose. Positives are structural
test shapes; no canonical decoding, checksum, account linkage, or liveness
is claimed. Scanner findings spanning a Markdown delimiter or omitting a
trailing character count as FP + FN under the existing exact-range protocol.

**Reference syntax** follows the safe examples in milestone-6 issues
[#278](https://github.com/redact-secret/redact-secret/issues/278),
[#279](https://github.com/redact-secret/redact-secret/issues/279),
[#280](https://github.com/redact-secret/redact-secret/issues/280), and
[#263](https://github.com/redact-secret/redact-secret/issues/263). Code
expressions, interpolation, and secret-manager pointers contain no literal
credential, so their expected arrays are empty. Six literal-secret controls
exercise `api_key`, `password`, and `client_secret`, including dots, quotes,
Unicode, and CRLF. These generic credentials intentionally test a different
capability than provider-prefixed formats; report categories separately.

All policy actions count as findings, including `warn`. A false positive here
does not necessarily mean the tool would redact that input. The benchmark
tests the installed published version, currently beta.1, and does not verify
whether unpublished fixes associated with an issue have resolved it.

The **Unreleased fixes** cohort follows the final issue decisions reviewed at
commit `530cafe9737eb5abc9702945394584aeb701d8c1`, not only the original issue
reproducers. See the [coverage matrix](../../docs/milestone-6-closed-coverage.md).
It has 59 negative fixtures and 33 positive fixtures, grouped by closed issue.
Its JSON records the target release, review snapshot, and unverified surfaces.
Connection-string positives mark only the password as secret; scanners
returning the entire connection URI receive a range mismatch rather than an
exact hit. Tutorial password exclusions follow redact-secret's intended
policy and are not universal scanner requirements.
